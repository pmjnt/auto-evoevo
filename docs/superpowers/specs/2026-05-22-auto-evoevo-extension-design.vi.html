Auto EvoEvo Extension — Thiết kế

Ngày: 2026-05-22 · Thay Playwright/CDP runner bằng một extension Chrome (MV3). Extension đóng vai trò ví ngay trên trang evoevo.ai, không cần Rabby cho site này.
Đọc nhanh: Hiện tại bạn đang chạy một process Node + Playwright, mở Chrome riêng, đọc text trong popup Rabby để biết bạn đang ký gì. Cách mới: cài 1 extension vào Chrome thường, extension này là ví — nó nhận giao dịch trực tiếp từ EvoEvo (object có sẵn các trường to, data, value, gas), kiểm tra theo guard, rồi ký bằng key đã unlock và đẩy thẳng lên RPC 0G. Không cần Rabby, không cần đọc text.

1. Mục tiêu & phạm vi

Mục tiêu

  • Tự bấm ADD TO MEMORY và SHOW MORE trên https://evoevo.ai/feed.
  • Thay Rabby trên site này: extension cung cấp window.ethereum (chuẩn EIP-1193) cho trang EvoEvo dùng.
  • Mỗi eth_sendTransaction đều phải qua guard hiện có; nếu pass thì ký tại chỗ bằng key đã unlock (lưu mã hoá).
  • Bất kỳ tình huống nào không chắc chắn ⇒ pause, không ký. Lý do hiển thị trên popup.

Không làm trong phiên bản này

  • Đẩy lên Chrome Web Store.
  • Hỗ trợ ví khác (WalletConnect, ví cứng, MetaMask Snap).
  • Hỗ trợ chain khác ngoài 0G.
  • Reverse-engineer ABI của contract EvoEvo. Mình coi data là bytes thô, chỉ kiểm bằng whitelist function selector (4 byte đầu).

2. So sánh cách cũ vs cách mới

Hiện tại — Playwright/CDP runner đang dùng

  • Có process Node chạy nền, Playwright mở 1 Chrome profile riêng.
  • Đọc popup Rabby bằng innerText rồi parse text bằng regex.
  • Các trường guard (origin, chain, contract, fee) đều suy ra từ text — dễ lệch khi Rabby đổi UI.
  • Gặp bất thường thì dừng; muốn tiếp phải restart cả process.
  • Lụy: cần Node, cần profile riêng, lệ thuộc Rabby UI.

Đề xuất — Extension MV3 mới

  • Cài vào Chrome bình thường của bạn — không cần profile riêng, không cần Node.
  • Extension chính là ví: nhận thẳng object giao dịch (to, data, value, gas).
  • Guard chạy trên object đã typed — không parse text, không phụ thuộc Rabby.
  • Pause/resume ngay trong popup. Key chỉ giữ trong RAM khi đã unlock.
  • Đánh đổi: phải tự implement EIP-1193 cỡ tối thiểu; user tắt Rabby trên site này.

3. Kiến trúc

Extension gồm 4 nơi chạy code tách biệt, chỉ nói chuyện với nhau qua message có schema rõ ràng. Mỗi nơi 1 việc, không ai biết internals của ai.

Giải thích nhanh các khái niệm Chrome extension:
  • Main world: chạy chung với JS của trang EvoEvo, thấy được window của trang. Đây là chỗ duy nhất có thể gán window.ethereum cho EvoEvo thấy. Nhưng main world không có quyền gọi API chrome.*.
  • Isolated world: cũng chạy trong tab EvoEvo, thấy DOM, nhưng không share biến với trang. Có quyền gọi chrome.runtime, chrome.storage... → đây là nơi tốt để bắc cầu.
  • Service worker (background): chạy nền, không gắn với tab. Đây là nơi giữ private key sau khi unlock, chạy guard, ký, gọi RPC. Chrome có thể tự kill service worker khi rảnh — thiết kế phải tính tới chuyện này.
  • Popup / Options: UI thuần HTML, hiện khi user bấm icon extension. Gọi background qua message.
Tab EvoEvo (trang) Background (service worker) UI của extension RPC bên ngoài / chain

Vì sao chia 4 chỗ như vậy

  • inpage phải ở main world mới gán được window.ethereum cho EvoEvo thấy. Nhưng main world không có chrome.* → phải nhờ content chuyển tiếp.
  • content ở isolated world: vừa thấy DOM (để click button), vừa có quyền message lên background.
  • background là nơi duy nhất chứa private key (đã decrypt) trong RAM service worker. Mọi thứ liên quan đến ký nằm gọn ở đây.
  • popup/options là HTML thuần, giao tiếp với background qua message — không bao giờ chạm trực tiếp vào key.

4. Luồng dữ liệu — 1 lần bấm ADD TO MEMORY

Đây là chuỗi sự kiện từ lúc automation click button cho tới khi tx lên chain.

Vài quyết định quan trọng trong pipeline

  • actionFingerprint = function selector (4 byte đầu của data). Bổ sung config allowedFunctionSelectors: string[]; guard reject nếu không khớp. Cải tiến đáng kể so với hiện tại — thay vì đoán mò "Unknown Signature Type" trên Rabby, mình có vân tay chính xác của function được gọi.
  • Guard thêm kiểm tra: data.length ≥ 4, value === 0n, selector ∈ whitelist. EvoEvo memory call không bao giờ chuyển native token và luôn có data.
  • Nonce và gas đều do background tự fetch qua RPC, không tin giá trị do trang gửi.
  • Origin verify bằng sender.tab.url (Chrome cung cấp, không bịa được), không tin field origin do content-script tự khai.
  • Reject về EvoEvo luôn là code 4001 (chuẩn EIP-1193 "user rejected") — không leak chi tiết guard reason ra trang. Chi tiết chỉ vào extension log + popup.
  • v1 chỉ ký eth_sendTransaction. Các method write khác (personal_sign, eth_sign, eth_signTypedData_*, wallet_*) trả code 4200 (unsupported). Nếu EvoEvo cần thêm method nào thì viết spec mới.

7. Máy trạng thái của automation

Đây là vòng đời của 1 session automation. Mọi sự cố guard/network/DOM đều đưa về paused, user resume từ popup. Hết button + 2 lần SHOW MORE không nạp thêm gì ⇒ done.

Chống ký trùng (idempotency)

  • Marker data-auto-evoevo-attempted-id ngăn click lại cùng 1 button (mượn từ controller.ts:5).
  • Entry inflight key bằng (nonce, keccak(data)). Khi SW wake mà thấy entry chưa có receipt → poll receipt, không ký lại.

9. Chiến lược test

Test theo boundary của từng module để đổi internals không phá test. Không chạy browser thật trong CI — chỉ unit + integration với fakes; manual smoke test trên Chrome lần cuối.

Unit

  • guard — port test cũ + check mới
  • crypto — round-trip, sai password, IV random
  • wallet — locked/unlock, idle-lock với fake timer
  • rpc — retry/backoff, nonce-too-low
  • messages — zod schema accept/reject

Integration

  • pipeline — fakes cho wallet/rpc/guard; verify gating
  • automation — DOM fixture; pause khi 4001; skip button đã marker
  • Replay khi SW wake với inflight set

Manual smoke

  • Load unpacked tại chrome://extensions → không lỗi
  • Import burner key 0G testnet → unlock
  • Dry-run ON: walk feed, log toàn dry_run
  • Dry-run OFF, 1 card: tx hiện trên explorer với to đúng, fee ≤ cap
  • Hạ cap thấp → pause với reason rõ

10. Câu hỏi cần xác nhận lúc làm

  • Chain id và RPC URL của 0G (mainnet vs testnet) — copy từ network của bạn đã add trong Rabby cho chắc, đừng đoán.
  • 0G có hỗ trợ EIP-1559 chưa? Nếu có: dùng maxFeePerGas/maxPriorityFeePerGas. Nếu chưa: legacy gasPrice.
  • EvoEvo có dispatch EIP-6963 không? Nếu không, README hướng dẫn user tắt Rabby trên site này.
  • Function selector EvoEvo gọi là gì? Lấy từ một tx thật trên explorer (field "Input Data") rồi seed vào allowedFunctionSelectors.

11. Tiêu chí nghiệm thu

  • Extension load vào Chrome MV3 không lỗi.
  • Dry-run ON: chạy hết feed, JSONL log tương thích shape SessionLogger hiện tại + thêm txHash và các status mới.
  • Dry-run OFF + 1 selector whitelist: mọi tx approved được ký + broadcast lên 0G; non-approve thì pause, không ký.
  • Guard dùng lại logic src/guard.ts; cùng WalletRequest ra cùng kết quả.
  • Private key không bao giờ rời background/wallet.ts; vault at rest mã hoá AES-GCM.
  • Tất cả unit + integration test pass với vitest run.
